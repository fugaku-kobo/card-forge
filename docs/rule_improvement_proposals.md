## A. リソース管理の強化

### 提案 1: 「インスピレーション加速」毎ターン自動 +1 IP

**元ネタ**: One Piece TCG — DON!! / Hearthstone — マナの自動増加

**内容**:
各ターン開始時(① ドローフェイズ直後)に自動で IP を +1 ずつ累積。
ターン経過で着実にコストを支払えるようになり、序盤の停滞を防ぐ。

**手塚への適合方法**:
- ① ドローフェイズ後に `s.ip += 1` を自動加算
- 上限は ターン数 × 2 程度(例: ターン 5 で MAX 10)
- インスピレーションゾーン送りは「追加で IP を稼ぐ」手段として残す
- ④ 担当編集フェイズ前に「自動取得 IP」表示

**期待される効果**:
- 序盤の主人公進化やキャラ展開を早める
- 「インスピ送り or 展開アイディアどちらを優先するか」の戦略的選択
- ゲームのテンポが改善

**実装難度**: 半自動判定(フェーズ進行と連動)
**リスク**: 既存のインスピ送り戦略との競合、テストプレイで上限値の調整必須

---

### 提案 2: 「インスピレーション保持上限」と「ターン跨ぎでの目減り」

**元ネタ**: Hearthstone — マナはターン内消費前提、繰越なし

**内容**:
インスピは累積するが上限あり(例: 15)。
ターン終了時に未使用 IP は **半分に切り捨て**(リソースを貯め込みすぎないよう)。

**手塚への適合方法**:
- `side.ip` に上限 cap(15 程度)
- ⑤ 就寝フェイズ終了時に `s.ip = Math.floor(s.ip / 2)`(または -1 ずつ減衰)
- 上限到達時、それ以上のインスピ送りで IP は増えず(警告表示)

**期待される効果**:
- 序盤に IP を貯めて終盤一気に発動する「ロックゲー」防止
- 中盤のテンポを維持
- ストック型と即時消費型の駆け引き

**実装難度**: 半自動(フェーズ終了処理)
**リスク**: テストプレイで減衰量の微調整、強カード(高コスト)のバリューが下がる懸念

---

### 提案 3: 「即時インスピ」 — 戦闘で没になったキャラから自動 IP 回収

**元ネタ**: Digimon Card Game — 進化時 1 ドロー / Yu-Gi-Oh — 破壊時効果

**内容**:
持ち込みバトルで没になったキャラの IP 値を、**没にした側ではなく没にされた側**が自動でインスピ取得。
「やられても次へのインスピレーション」という手塚らしいテーマ。

**手塚への適合方法**:
- `startBattle` で防御側のカードが没案に行くとき、防御側の `side.ip += card.ip` を自動加算
- ログに「💧 没にされた N から IP +M を得る(逆境がアイデアを生む)」
- 既存のインスピ送りは別途残す(任意IP獲得)

**期待される効果**:
- 一方的な持ち込みバトルの抑制(やられた側も得るものがある)
- 「主人公の挫折が次のアイデアを生む」手塚作品的演出
- 場が全没でも次ターンのリソースが残る安心感

**実装難度**: 自動判定(startBattle に組込)
**リスク**: 戦闘ゲインが弱まる(原稿カウンタが優位なので大きな問題ではない)

## B. 戦闘システムの拡張

### 提案 4: 「持ち込みバトルのパワー対決方式」 — HP管理から差分計算へ

**元ネタ**: Digimon Card Game / Cardfight!! Vanguard / One Piece — パワー対決

**内容**:
HP 数値の管理をやめ、**攻撃側パワー ≥ 防御側パワー** で防御側を没にするシンプル方式。
パワーは card.hp(または card.power)を流用、ターン中の修飾は IP コストでブースト。

**手塚への適合方法**:
- キャラの「HP」を「パワー」に読み替え
- バトル時: 攻撃側パワー vs 防御側パワー
  - 攻撃側 ≥ 防御側 → 防御側が没へ
  - 攻撃側 < 防御側 → 攻撃側が没へ(反撃)
- IP を消費して攻撃側パワーを +20 ブースト(One Piece の DON!! 風)

**期待される効果**:
- HP 数値の手動管理が不要(計算ミス減)
- 「攻撃力ブースト」戦略の追加
- 戦闘の解決が早くなりテンポ改善

**実装難度**: 自動判定(startBattle に組込)
**リスク**: 現行 HP ベースのキャラデータと不整合、移行コストあり

---

### 提案 5: 「テコ入れカード」をスタック発動システムに

**元ネタ**: MTG — スタック / Yu-Gi-Oh — チェーン

**内容**:
現在「テコ入れ」は伏せて相手ターンに発動できる程度の扱いだが、明確に **スタック(チェーン)発動システム** に。
攻撃側のアクションに対して、防御側がテコ入れを発動 → さらに上から効果を重ねていく。

**手塚への適合方法**:
- 専用「テコ入れゾーン」を場に追加(伏せて置く専用)
- 持ち込みバトル宣言時にチェーンチェック: 防御側にテコ入れがあれば発動可
- 発動後はテコ入れカードを没案へ
- どんでん返しも同じシステムで発動可能(原稿6枚以上の条件は維持)

**期待される効果**:
- 戦闘に「反応」の駆け引きが生まれる
- 単純な攻撃の押し付けを抑制
- TCG らしい戦略の深さ

**実装難度**: 半自動(スタックの解決順序を明示、UI上のチェーン表示)
**リスク**: ルール複雑化、新規プレイヤー学習コスト

---

### 提案 6: 「主人公への直接攻撃」 — 場が空のときに主人公を狙える

**元ネタ**: One Piece — リーダー直接攻撃 / Hearthstone — ヒーローへの攻撃

**内容**:
持ち込みバトル時、防御側の場(キャラ)が空であれば **直接主人公を攻撃可能**。
主人公にダメージが入ると、防御側の山トップが「ライフ」として手札に加わる(または原稿に裏向きで送る)。

**手塚への適合方法**:
- ③ 持ち込みバトル時、相手の場が空 + 自分の場にキャラがいれば、攻撃ターゲットに「主人公」を選べる
- 主人公への攻撃成功時: 防御側の山トップ 1 枚を主人公HPカウンタに付与(=ライフ消費表現)
- 主人公のライフが尽きたら防御側敗北(原稿10とは別経路の勝利条件)
- 「泣きの一回」は主人公攻撃が来ないようにする防御策

**期待される効果**:
- 場のキャラがいない無防備な状態でも緊張感
- 原稿勝利以外の選択肢(早期決着型デッキの誕生)
- 主人公カードに HP/ライフ値を持たせる意味が生まれる

**実装難度**: 自動判定(startBattle 拡張、勝利条件追加)
**リスク**: ゲームバランスが大きく変わる、現行の HP=0 自動インスピと整合性確認

## C. 進化システムの深化

### 提案 7: 「ライドデッキ式の主人公管理」 — 専用山から確実に進化

**元ネタ**: Cardfight!! Vanguard — ライドデッキ

**内容**:
主人公 Lv1/2/3 を**専用の進化山(ライドデッキ)** に格納し、毎ターン 1 枚ずつ確実に取り出して進化できる。
現状の「主人公控え」を「進化山」化し、ターン進行で自動的に進化。

**手塚への適合方法**:
- `side.leaderReserve` を「ライドデッキ」風に改名し、Lv 順で固定
- 各ターンの ④ 担当編集フェイズで「次の Lv に練り上げ」アクションを実行可能
- 主人公の進化に IP 消費要(各 Lv ごとに必要 IP が増える: Lv2=3, Lv3=6 等)

**期待される効果**:
- 主人公進化のテンポが安定(運要素を抑える)
- 「練り上げ」が戦略的選択(IP を進化に使うか展開に使うか)
- 終盤に向けた Lv3 主人公の到達がほぼ保証

**実装難度**: 中(既存実装に近いが進化条件のIP消費を追加)
**リスク**: 主人公進化の運要素が消えるので、サプライズ性が減る

---

### 提案 8: 「進化時 1 ドロー」ボーナス

**元ネタ**: Digimon Card Game — 進化時 1 ドロー

**内容**:
主人公・キャラの進化を成功させた瞬間に **山から 1 枚ドロー**(進化ボーナス)。
進化を「ご褒美」感のあるアクションにする。

**手塚への適合方法**:
- `moveInstance` で進化が成立した時(toZone='field' で evolutionTargetIdx >= 0、toZone='leader' で Lv +1)に追加ドロー処理
- ログ「🌟 進化ボーナス: 1ドロー (山残 N)」
- 山が空のときは何もしない

**期待される効果**:
- 進化のインセンティブを増やす
- 手札枯渇のリスクを軽減
- 「練り上げ」が戦略的に魅力的に

**実装難度**: 小(既存進化ロジックに追加するだけ)
**リスク**: ハンド有利が強くなりすぎる場合、ドロー枚数を調整

---

### 提案 9: 「進化条件カード」 — 進化に特定カードの没を要求

**元ネタ**: Yu-Gi-Oh — アドバンス召喚(リリース) / MTG — Tribal commander

**内容**:
Lv3 への進化(清書 / 相棒)に、**追加で特定カードの没** を要求するルール。
例: アトム Lv3 への進化は「お茶の水博士」を 1 枚没にする必要あり。
カード間のシナジーで物語性を強化。

**手塚への適合方法**:
- カードに新フィールド `evolutionRequirement` を追加(オプション)
- 進化時に該当カード(同名 / シリーズ)が場 or 手札にあれば没にして進化可
- 条件を満たさない場合は通常通り進化不可

**期待される効果**:
- 手塚作品の関係性(BJ + ピノコ、アトム + お茶の水博士)をルール化
- デッキ構築の戦略深化(進化先 + サポートキャラの組み合わせ)

**実装難度**: 中(カードデータに新フィールド、進化処理に条件チェック)
**リスク**: カードデータの再整備必要、複雑化

## D. 勝利条件の選択肢

### 提案 10: 「Lore 風 クエスト勝利」 — 原稿以外の道

**元ネタ**: Disney Lorcana — Lore 獲得によるクエスト勝利

**内容**:
持ち込みバトルとは別に、自分のキャラを「**クエスト**(使い切り状態にする)」ことで Lore(原稿)を獲得する経路を追加。
場のキャラを「攻撃役」と「原稿稼ぎ役」のどちらに使うかが戦略の核に。

**手塚への適合方法**:
- ② アイディアフェイズに「キャラを **クエストに使い切る** (一度きり)」アクション
- 使い切ったキャラは次ターン開始時にスタンド(再使用可)
- クエストで原稿 +1(キャラの IP 値分か固定 +1)
- 持ち込みバトル成功でも原稿は獲得(現行通り)

**期待される効果**:
- 戦闘苦手なプレイヤーでも原稿稼ぎが可能
- 場のキャラの活用法に多様性
- 緊張感のある選択(攻撃 or クエスト)

**実装難度**: 中(新ステート「使い切り」の管理)
**リスク**: 原稿勝利が早すぎる可能性、クエスト効率の調整

---

### 提案 11: 「主人公の魂レベル」勝利 — Lv3到達で原稿+α

**元ネタ**: Weiss Schwarz — レベル進化勝利 / Yu-Gi-Oh — エクゾディア

**内容**:
主人公が Lv3(清書)に到達した時点で、**原稿 +3 ボーナス**(または特殊勝利条件)。
主人公の進化を成功させること自体に大きな価値を与える。

**手塚への適合方法**:
- 主人公が Lv3 になった瞬間に `side.manuscriptCards` に山から 3 枚移動(物理的な「完成」)
- もしくは: Lv3 主人公が場で 2 ターン生存したら特殊勝利(「絶対傑作」)
- 進化スタックを最終決戦の演出に

**期待される効果**:
- 主人公進化が単なる強化ではなく「勝利への直接ルート」
- 防御側に主人公没のプレッシャー
- ドラマ性の強化(主人公が無事に最終回まで描けたら勝利)

**実装難度**: 小〜中(進化検出に勝利トリガー追加)
**リスク**: 主人公進化が万能になる、バランス調整必須

## E. 手塚独自の世界観強化

### 提案 12: 「担当編集アクション」 — ④フェーズの専用カード

**元ネタ**: 現行ルール拡張 + Hearthstone — ヒーローパワー

**内容**:
④ 担当編集フェイズに、各主人公専用の「**担当編集スキル**」を 1 ターン 1 回起動可能。
例: BJ の編集 = 山からキャラ1枚を手札に / アトムの編集 = 場のキャラ1体に HP+10 など。

**手塚への適合方法**:
- 主人公カードのデータに `editorAction: { cost, effect, name }` フィールド追加
- ④ フェーズで「担当編集」ボタン表示(IP 払って効果発動)
- 編集者(別カードタイプ)を場に出している場合、効果が強化される追加ルールも

**期待される効果**:
- 主人公カードに能動的な使い方が生まれる(現状は受動的な戦力)
- 各主人公の個性が際立つ
- 「担当編集」フェーズが空フェーズでなく実体化

**実装難度**: 中(主人公データに能力フィールド、UI に新ボタン)
**リスク**: 主人公カードの再整備必要

### 提案 13: 「持ち込みペナルティ」 — 失敗時のリスク

**元ネタ**: 独自ルール + Pokémon — 弱点/抵抗

**内容**:
持ち込みバトルが失敗(攻撃側の方が没になるケース)した時、攻撃側の山トップ 1 枚を **没案に送る**(「企画却下」)。
持ち込みを濫発できないようにする。

**手塚への適合方法**:
- パワー対決方式(提案4)と組み合わせ: 攻撃側 < 防御側 のときに発火
- 没になった攻撃側カード + 山トップ 1 枚を没案へ
- ログ「📕 持ち込み却下: 山トップが没案へ」

**期待される効果**:
- 持ち込みバトルが慎重な選択に
- 防御側にも勝つチャンス
- 「持ち込みは失敗が怖い」というテーマの演出

**実装難度**: 小(パワー対決の解決時に追加処理)
**リスク**: 持ち込みが消極的になりすぎる懸念、テストプレイ次第

### 提案 14: 「作品シナジー」 — 同作品キャラのコンボ

**元ネタ**: MTG — 部族シナジー / 各種TCG — クラス制

**内容**:
同じ「作品名(work)」のキャラが場に複数いるとボーナス(+IP / +パワー / 特殊効果)。
BJ と ピノコ が両方場にいたら…のようなシナジー。

**手塚への適合方法**:
- `c.work` 値が同じキャラが場に N 枚いると効果発動
- 例: BJ作品キャラが 3 体場にいる → 持ち込み +1 原稿、アトム作品キャラ 2 体 → IP +1
- カード個別効果ではなく、システムレベルでの作品ボーナス

**期待される効果**:
- デッキ構築に「作品縛り」の戦略
- 手塚作品ファンへのアピール(BJ デッキ、アトム デッキの存在感)
- カードコレクション要素

**実装難度**: 中(`getDeckTotalCount` で作品別カウントは既にあるが、ゲーム中の動的計算が必要)
**リスク**: 計算が複雑化、シナジーの上限管理

---

### 提案 15: 「原稿カード」のトリガー効果

**元ネタ**: Cardfight!! Vanguard — トリガー / Weiss Schwarz — クライマックス

**内容**:
持ち込みバトル成功でデッキトップを原稿ゾーンに送る時、**原稿カードに付いた特殊アイコン** で追加効果発動。
例: 「✏ ドロー1」「💡 IP+1」「⚔ 攻撃ブースト」など。

**手塚への適合方法**:
- カードデータに `trigger: '✏drow' | '💡ip' | '⚔attack' | null` フィールド
- `startBattle` で原稿に送る時、トリガーチェック → 効果発動
- カード作成時に手動でトリガー指定
- 一部のカード(例: 全カードの 20%)のみトリガー持ち

**期待される効果**:
- 持ち込みバトルにドラマ性(「やった!原稿が引けた!」)
- 山札の上の運要素が戦略要素に
- 各原稿が単なる勝利ポイントでなく「物語の出来事」になる

**実装難度**: 中(カードデータ拡張、startBattle にトリガー処理)
**リスク**: バランス調整必須、トリガー設計に時間
